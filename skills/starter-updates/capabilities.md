# What the starter offers

The starter-updates skill reads this file from its scratch clone of the starter,
as data, and asks about each row. A folder path ends in a slash. A path can be
in two rows, because more than one capability needs it.

| Name | Kind | Chip | Gives | Tell me more | Paths |
|---|---|---|---|---|---|
| The loop | a script, a skill and a pane | The loop | Takes a ready issue, plans it, builds it, checks it and opens a pull request for a human to review. | The script does the work. The loop-control skill drives it from a conversation: it puts an issue on after checking it's ready, starts the loop, says what it did or why an issue is blocked, and stops it in the right order. The pane opens with /loop-pane and shows the queue, each issue's step and round, its tokens and estimated cost, and its pull request. It never changes the loop. | [`scripts/loop.py`](../../scripts/loop.py), [`skills/loop-control/`](../loop-control/), [`examples/mods/loop-pane/`](../../examples/mods/loop-pane/) |
| Observability | mods and scripts | Visibility | Shows what the harness is doing and what it has used, above the prompt, in a pane and from scripts you run. | The harness-lens mod shows which layer just acted. The github-status mod shows the repo's running actions, open pull requests and open issues, read through gh. The harness-dashboard mod opens with /harness-dashboard and shows what's waiting on you, the loop's spend, throughput and rework, the saved evals and Claude Code's tokens; it's off by default. The usage hook keeps one line per harness event on this machine, the report scripts summarize that log and Claude Code's tokens, and the eval script runs a review agent on known examples and says which defects it still catches. | [`examples/mods/harness-dashboard/`](../../examples/mods/harness-dashboard/), [`examples/mods/harness-lens/`](../../examples/mods/harness-lens/), [`examples/mods/github-status/`](../../examples/mods/github-status/), [`scripts/dashboard_data.py`](../../scripts/dashboard_data.py), [`scripts/token_report.py`](../../scripts/token_report.py), [`scripts/usage_report.py`](../../scripts/usage_report.py), [`scripts/eval_agents.py`](../../scripts/eval_agents.py), [`scripts/loop.py`](../../scripts/loop.py), [`.claude/hooks/usage_log.py`](../../.claude/hooks/usage_log.py) |
| Reviews | skills and agents | Reviews | Reviews a pull request and its tests, and reads finished work before a human sees it. | The review-pr skill returns findings ranked by cost with a verdict, and never approves, merges or posts. The review-tests skill breaks the code on purpose in a scratch copy and reports which tests protect something and which only pass. The reviewer agent reads finished work as the person who receives it would. The security-reviewer agent reads code the way an attacker would and reports each finding with its attack path, and a READY or NOT-READY verdict. | [`skills/review-pr/`](../review-pr/), [`skills/review-tests/`](../review-tests/), [`agents/reviewer.md`](../../agents/reviewer.md), [`agents/security-reviewer.md`](../../agents/security-reviewer.md), [`.claude/agents/reviewer.md`](../../.claude/agents/reviewer.md), [`.claude/agents/security-reviewer.md`](../../.claude/agents/security-reviewer.md) |
| Leadership seats | agents | Leadership | Reads finished work from the seats of the chief executive, chief technology officer, chief marketing officer and general counsel. | The ceo agent reports what the work commits the company to that nobody decided, and what it costs. The cto agent reports what won't hold, what can't be run or undone, and technical claims the work doesn't show. The cmo agent reports claims a customer could check and find wrong. The gc agent looks at licences, promises, other parties' names or content, and personal data, and ends with the findings that need a lawyer; it isn't a lawyer or legal advice. None of them edits. | [`agents/ceo.md`](../../agents/ceo.md), [`agents/cto.md`](../../agents/cto.md), [`agents/cmo.md`](../../agents/cmo.md), [`agents/gc.md`](../../agents/gc.md), [`.claude/agents/ceo.md`](../../.claude/agents/ceo.md), [`.claude/agents/cto.md`](../../.claude/agents/cto.md), [`.claude/agents/cmo.md`](../../.claude/agents/cmo.md), [`.claude/agents/gc.md`](../../.claude/agents/gc.md) |
| Morning read | skills | Morning read | A morning read of what's on you and what in your mail needs a reply, then a suggested order for the day. | The standup skill covers reviews waiting, issues assigned, what the loop finished or blocked, and today's meetings. The inbox skill says what needs a reply from you, what's waiting on someone else and what's worth knowing, one line per thread, and reads mail only where the company's data file clears the source. Neither changes anything. | [`skills/standup/`](../standup/), [`skills/inbox/`](../inbox/) |
| Reports | skills and scripts | Reports | A one-page report of what got done in a repo, and a sprint report on how you used the harness. | The work-report skill is for a lead or a team: what merged by type and who made and approved it, what the loop built, the milestones GitHub recorded, the specs it touched and a chart of merges. The harness-report skill is for the harness owner: it reads your own usage log, Claude Code's token counts and the loop's cost records, adds what you'd add, change or drop, and you read it before it goes anywhere. | [`skills/work-report/`](../work-report/), [`skills/harness-report/`](../harness-report/), [`scripts/work_report.py`](../../scripts/work_report.py), [`scripts/usage_report.py`](../../scripts/usage_report.py), [`scripts/token_report.py`](../../scripts/token_report.py), [`scripts/dashboard_data.py`](../../scripts/dashboard_data.py), [`scripts/eval_agents.py`](../../scripts/eval_agents.py), [`scripts/loop.py`](../../scripts/loop.py), [`scripts/plugin_report.py`](../../scripts/plugin_report.py), [`.claude/hooks/usage_log.py`](../../.claude/hooks/usage_log.py) |
| Session retro | a hook and a skill | Retro | Finds out why the agent got something wrong in an ordinary session, from that session's own log, and queues the answer for the learn skill. | Off unless HARNESS_RETRO=on. When a session where you corrected the agent ends or compacts, the hook keeps a copy of its log on this machine, readable by you alone, and deletes it once read or after 30 days. Say "retro" and a fresh agent that can only read says why the agent didn't know: nothing said it, it wasn't loaded, it was ignored, something said the opposite, or nothing could have. What the log bears out goes in the loop's lessons file. | [`skills/retro/`](../retro/), [`.claude/hooks/session_retro.py`](../../.claude/hooks/session_retro.py) |
| Daily question | a skill and a script | Pulse | Asks a team one multiple-choice question a day from a shared folder, shows the counts, and writes a summary of a period's answers for leadership. | Each person's answers land in a file named after their login in that folder, which anyone with the folder can read. It needs no server or connector, and the skill acts only where the company's data file clears the folder. The summary never prints a login, holds back a question fewer than three people answered, quotes Other answers as written, and stays gitignored until the person reads and sends it. | [`skills/pulse/`](../pulse/), [`scripts/pulse.py`](../../scripts/pulse.py), [`reports/pulse/`](../../reports/pulse/) |
